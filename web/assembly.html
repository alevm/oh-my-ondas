Assembly Manual

This manual describes the v0.3 plan (ESP32 WiFi link, two MCP23017, NeoPixels). It will be rewritten for v1. Current wiring: Prototype.

Oh My Ondas Hardware Prototype — March 2026 — Barcelona

TEENSY 4.1 — COMPLETE PIN ASSIGNMENT — Pins 7, 8, 20, 21, 23 RESERVED by Audio Shield I2S

Before You Start

Confirm these counts. If anything is short, note it before beginning.

  • Slide pots 45mm (P4272): ordered 5 — confirm you have 5
  • Wire Kit 22AWG (P3174): check Adafruit box
  • Helping Third Hand (P291): check Adafruit box

Key Decisions

  1. Use Teensy built-in SD (SanDisk Ultra 32GB). Audio Shield SD slot unused.
  2. LCD is 2.8″ ILI9341 (P1770) — DMA-optimized ILI9341_t3 library.
  3. Dual I2C: Wire (18/19) audio-path, Wire2 (24/25) UI-polling (pins 16/17 are covered by the Audio Shield sockets).
  4. 4 main buttons direct to Teensy pins for latency + interrupts.
  5. ESP32-S2 powered from 5V, not Teensy 3.3V.

Tools

Soldering station 48W, solder 1mm, flux, 2× breadboard, jumper wires, helping hand, micro-USB cable, 3.5mm headphones.

Core Audio

GOAL: Hear a WAV file through headphones

Teensy 4.1Audio Shield Rev DSD Card (32GB)Headphones
1.1 — Stack the Teensy on the Audio Shield

The Audio Shield Rev D sits under the Teensy 4.1. A female socket strip on the shield receives the Teensy's downward-facing male headers. The stack is pluggable — there is no solder joint between the two boards.

  1. Orientation: shield at the USB end, pin 0 to pin 0.
  2. Coverage: the shield covers only the first 14 pins per side. Teensy 4.1 pins 24 and up stay free.
  3. Seat the Teensy fully: the header plastic must touch the socket strip. Partial insertion gives intermittent contact — the codec can answer on I2C while audio still fails.
Shield functionTeensy pins
Audio data (I2S)7, 8, 20, 21, 23
I2C control (shared) — SGTL5000 at 0x0A18 (SDA), 19 (SCL)
Shield SD socket10, 11, 12, 13
Memory chip CS6
Volume pot15 / A1

Source: pjrc.com/store/teensy3_audio.html

Shared pins later in the build: the LCD uses pin 10 (CS, shared with the shield SD socket) and pin 15 (RST, the volume-pot pin); the NeoPixels use pin 6 (memory chip CS). Keep the shield SD socket empty, and do not fit the volume pot or the memory chip.

VISUAL CHECK — SHIELD UNDER TEENSY, USB END, HEADERS FULLY SEATED

1.2 — Prepare SD Card
  1. Format as FAT32 (not exFAT).
  2. Copy TEST.WAV (44.1 kHz, 16-bit) to the root. No card reader? With the card in the Teensy, upload firmware/teensy/test/sd_upload and run firmware/tools/sd_upload.py --test-wav.
  3. Insert into Teensy built-in slot (not Audio Shield slot).
1.3 — Connect
  1. Rest the stack on a non-conductive surface (with the shield underneath it does not go into a breadboard).
  2. Headphones into Audio Shield 3.5mm jack.
  3. USB to computer.
1.4 — Flash and Test
#define SDCARD_CS_PIN    BUILTIN_SDCARD
// Shield SD socket (CS 10, SPI 11-13) stays empty:
// pin 10 is the LCD chip select

Test sketches in firmware/teensy/test/, Serial Monitor at 115200 baud:

  1. layer1_tone — prints SGTL5000 OK and plays a 440 Hz sine on both channels.
  2. layer1_sd_playback — prints SD OK and loops TEST.WAV from the built-in slot.
  3. layer1_record_roundtrip — records a generated 880 Hz tone to REC.RAW, checks size and frequency, plays it back (File: PASS, Playback: PASS).
If no sound: check Serial Monitor for SGTL5000 NON risponde or SD FAIL. Verify the Teensy is fully seated, FAT32 format, correct slot, headphone jack fully inserted.

2.1 — Wire CAP1188 to Wire2

Wire2 sits on free pins just past the Audio Shield, so the stack stays pluggable: female Dupont jumpers push straight onto the Teensy's downward-facing pins.

CAP1188 PinTeensy PinNotes
SDA25 (SDA2)Wire2 bus
SCL24 (SCL2)Wire2 bus
VIN3.3VNext to pin 24, past the shield
GNDGNDOpposite side, next to pin 41
One set of pull-ups per bus. If the CAP1188 breakout already has pull-ups on SDA/SCL, add none. If it doesn't, add 2.2KΩ from pin 25 and from pin 24 to 3.3V.
2.2 — Make Touch Pads

Cut 8 pieces of copper tape (~20×20mm). Stick on cardboard in 2×4 grid, 5mm spacing. Solder wire to each. Connect to C1–C8.

4.2 — Wire Slide Pots

Each pot: Left → GND, Right → 3.3V, Wiper → ADS1115 A0–A3. Pot 5 wiper → Teensy pin 14 (A0).

Pots to 3.3V only! The ADS1115 and Teensy ADC are 3.3V max. 5V will damage them.

Add 100nF ceramic cap from each wiper to GND, close to the ADC input.

4.3 — Test
Adafruit_ADS1115 ads;
ads.begin(0x48, &Wire);
// ads.readADC_SingleEnded(0) ... sweep 0 to ~26000

If jumpy: check 100nF caps, keep wiper wires away from SPI lines.

5.2 — Install MCP23017s into DIP Sockets

Watch the notch — pin 1 at the notch end. Both on Wire2 (24/25), shared with the CAP1188. #1 at 0x20 (A0/A1/A2 = GND). #2 at 0x21 (A0 = 3.3V). RESET pins → 3.3V. 100nF cap on each VDD–VSS.

5.3 — Wire Encoders

Each EC11: C (common) → GND, A + B → MCP GPIO, SW → MCP GPIO. Enable MCP internal pull-ups in firmware. 5 encoders on MCP#1, 2 on MCP#2.

5.4 — Wire 5-Way Nav

Common → GND. Up/Down/Left/Right/Select → MCP#2 GPIOs. Internal pull-ups.

✓ VALIDATION: 7 encoders rotate + click, 4 buttons respond, nav switch 5 directions

If You Get Stuck

  • No sound (Day 1): SD must be FAT32, files on root, CS = BUILTIN_SDCARD.
  • I2C device not found (Day 2+): Check wiring. Wire2 needs one set of pull-ups (on the breakout or 2.2K added).
  • Audio glitches with NeoPixels (Day 4): Switch to WS2812Serial library.
  • Fader jitter (Day 4–5): Add 100nF caps on wipers. Keep analog wires away from SPI.
  • ESP32 causes Teensy reboot (Day 8): Power ESP32 from 5V, not 3.3V.
  • GPS no fix (Day 8): Go outdoors or to window. First fix needs sky view.
  • Encoder knobs don't fit (Day 6): Check for set screw hole. May need D-shaft adapter.
